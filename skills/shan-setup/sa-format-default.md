# 需求分析書格式契約（預設）

專案還沒有既成的需求分析書慣例時用這份。`shan-setup` 會把它複製進專案（預設 `docs/specs/SA-FORMAT.md`），之後就是**專案的資產**——要改直接改專案裡那份，不要改 skill 裡的樣板。

這份預設的章節順序來自常見的「需求分析報告書」Word 範本。你的團隊範本不同，就改成你們的；`shan-to-sa` 與 `shan-to-req` 只讀契約，不依賴本檔的任何標題。

## 這份文件是什麼

需求分析書是 **SA 寫給客戶與內部看的功能說明**，一份文件對應一個功能。它是 `requirements.md`（給 PG 的 user story）的上游來源之一，但兩者不同：需求分析書描述功能長什麼樣，`requirements.md` 把它拆成可驗收的行為。

檔名：`<功能名稱>_SA.md`（命名規則以 config A 節為準）。

## 標題契約

md 的標題層級對應 Word 的樣式層級（`# ` = 第一層，`## ` = 第二層，依此類推），轉 docx 時由對應檔決定套哪個樣式。編號（一、(一)、1.、(1)）由 Word 樣式自動產生，**md 標題文字不要自己加編號**。

```markdown
# 需求說明
<一到兩段：這個功能為什麼要做、對誰、來源（反應單／問題單編號）>

# 功能規格

## <功能名稱>

### 應用系統介面
<這個功能在哪個系統、哪個選單／畫面入口>

### 資料流說明

#### 畫面欄位與定義
<以文字概述畫面欄位與定義；欄位多時用表格：序號｜欄位名稱｜說明>

#### 主要流程說明
<以文字概述主要流程；條件分支用清單>
```

- 一個需求分析書可有多個 `## <功能名稱>`，每個功能一組
- 畫面截圖不由 AI 產生：在需要放圖的位置寫 `![說明](待補)`，轉成 docx 後會變成預留文字，由 SA 人工貼圖
- 內文一行一個段落；清單用 `-`；表格用 markdown 表格
- **不要寫**：SQL、類別名稱、API 路徑——那些屬於系統設計書
